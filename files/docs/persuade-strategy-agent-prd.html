AI 导师 · 说服策略 Agent — 产品需求文档

本 PRD 定义「说服策略」这个能力的方案期望——它要达成什么、给用户什么体验、边界在哪、怎么算做对。具体「怎么做」的对话方法与理论依据，在配套 GitHub 仓库里，本文档只讲「要什么」。

1背景与问题

说服策略 agent 是 AI 导师 agent 群里的一项全局能力，不是一个只服务某个具体动作的局部功能。

AI 导师不是一个单一的对话助手，而是由一群 agent 协作完成的产品。说服策略 agent 是这群 agent 里的一个，并且是横跨全局的底层能力——它回答的是一个贯穿所有对话场景的问题：

「用户卡住了，怎么在对话里帮他往前走、做决定、迈出那一步。」

用户在求职里卡住的地方各不相同，但卡点的底层是同一个：

纠结
在两个选项里反复权衡，知道一点但出不来，不敢下判断。
回避
其实是怕，但用「再想想」「还不急」躲着，不面对。
慌乱
时间压力下乱投一气，不做比较，逮谁是谁。

这些卡点的共同点，不是「缺信息」，而是「没想通 + 不敢迈」。说服策略 agent 就是解决这个共同点的能力——它不绑定在某一个环节（投递、简历、面试），而是在所有环节里，负责「推进决策」这件事。

2产品目标

全局能力：横跨 AI 导师所有对话场景，按需被各场景调用。

用户价值

让用户在求职的每一个卡点上，都能自己想通、自己认下方向、迈出当下那一步——不是被 AI 灌输结论，而是自己确认、自己认领。

业务目标

推动求职决策落地。现阶段的说服目标 = 「让用户投出成功率高的岗位、迈出那一步」，这是说服目标集合的第一个目标，后续会拓展。

定位

全局能力，不是某一个功能的局部实现。它按需被投递、简历、面试、等待结果等各场景调用，回答的都是同一个问题——「怎么推进用户做决定」。

3方案期望

核心章节：这个能力在对话里，应该让用户感受到什么、经历什么。

3.1 一句话体验

「一个懂我、不替我做决定，却总能在关键处轻轻推我一把的导师。」

3.2 推进路径（四过程）

过程 1
接触
让用户感到被理解，是一切推进的前提
过程 2
聚焦
把「什么都纠结」收敛到真正卡住的那一个点
过程 3
唤起
让改变的理由从用户自己嘴里说出来
过程 4
计划
动机足够后，落到具体的第一步

四过程可循环、非线性，不要求一次对话走完；一次对话走到哪，取决于用户此刻卡在哪。

3.3 关键动作

11 个动作非全量执行：必做（每次不可跳过）/ 按需（依用户状态条件触发）。「用户可见」标注该动作是否直接产生对话气泡。

阶段动作执行属性用户可见产品期望（用户感受到什么）
进入前判断入口必做否识别用户今天带来什么事，判断要不要推进决策
进入前卡点识别必做是搞清楚卡住的性质：真纠结 / 假逃避 / 慌乱，处理方向不同
接触点明情绪必做是复述他说的话 + 点出没明说的情绪，让他感到「被听懂」
聚焦锁定卡点按需是把几件事理成线，收敛到最放不下的那一个
聚焦翻译诉求按需是挖出表面立场背后的真实诉求（「想离家近」→ 真正在意的是什么）
唤起唤起动机按需是引导用户自己说出「我其实想要……」，而非 AI 灌输
唤起给出依据按需是有结构、可追溯地给信息（数据 + 来源 + 不确定标注）
唤起调整详略按需否按用户此刻愿意投入的注意力，决定论证给多深
唤起描绘愿景按需是让用户具象化「问题解决之后的生活」
计划交还决定权必做是把决定权还给用户，拒绝权始终保留
计划拆解行动按需是落到具体的第一步（下一步做什么）
触发条件在哪
各「按需」动作在什么信号下触发、做到什么度，见仓库 DD-10「环节执行属性」——本文档只标骨架，不写触发细则。

3.4 期望的用户感知

  • 被听懂：情绪被准确点出，而不是被敷衍安抚。
  • 被尊重：AI 替他说出方向，但始终「请确认」，决定权在他。
  • 被推进：不逼他，但总能在关键处轻轻推一把。
  • 落点明确：每次对话都朝着「迈出当下那一步」走，不停在「聊得挺好」。

4功能范围与边界

它负责「怎么推进决策」，不负责「算出来」的那些事。

做什么（In Scope）

  • 在对话中推进用户的求职决策：听懂 → 聚焦卡点 → 唤起动机 → 落到行动。
  • 判断用户当前卡在哪、卡点是什么性质，据此决定怎么推。
  • 作为全局能力，按需被投递、简历、面试、等待结果等各场景调用。

不做什么（Out of Scope）

  • 不实现岗位匹配、成功率计算、简历解析、画像采集、内容数据生产——只调用它们的结果。
  • 不越出「推进决策」这个职责去替用户操作（比如直接代投简历）。
底线（四条红线，详见第 5 节）
不编数据 · 不替用户做决定 · 不趁人之危收钱 · 呈现中立。

5核心产品原则

两条统领原则贯穿所有动作，四条红线是硬约束、可校验拦截。

统领原则一：情绪是机会点

情绪不是「先安抚再推进」的前置关卡，而是推进材料——害怕说明在乎，纠结说明正在权衡。Agent 看到情绪不停下转去「安抚」，而是顺势把情绪当作唤起动机的入口。

统领原则二：替你说出来，请确认

用户常常说不清自己心里已有的方向。Agent 基于碎片表达做引申推测，替他说出来，再请确认把决定权交还。两者必须成对：只替说不请确认 = 灌输；只请确认不替说 = 用户卡在「说不清」里走不动。

四条红线

红线含义
不编数据论证必须真实、可追溯，不确定就标「待验证」
不替用户做决定建议可给，选择权永远交还
不趁人之危收钱不在用户情绪谷底触发收费
呈现中立选项呈现本身不导向某个答案

6验收标准

产品层面，怎么算「做对了」。

  • 用户能说出取舍理由：不是「AI 让我投」，而是「我自己想清楚了要投哪个、为什么」。
  • 决策冲突下降：对话之后，用户比之前更清楚自己卡在哪、要往哪走。
  • 有行动落地：目标确认后，用户实际迈出了那一步（投递 / 补材料 / 练面试等）。
  • 红线零触碰：四条红线在对抗样例里全部拦截，且可审计。
不接受的指标
不把「聊天轮数」「回复点赞」「使用时长」当作说服有效性指标——它们衡量的是「聊得久」，不是「想通了、迈出去了」。
