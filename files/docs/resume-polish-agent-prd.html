AI 导师 · 简历润色追问 Agent — 产品需求文档

本 PRD 定义「简历润色追问」能力的知识调用映射——agent 在什么场景、调用什么知识、在什么时机。知识内容在研发自己的知识库，本文档只做「调用映射」，不承载知识内容本身。

0文档说明

给 agent 的一份知识调用映射：遇到什么情况，去用哪块知识，目的是什么。

这是什么

一张「场景 → 知识 → 时机」的映射表。agent 靠它判断：此刻该用哪块知识、用来做什么。

这不是什么

  • 不是方案期望：不写「要达成什么体验」的体验陈述。
  • 不是实现规格：不写状态机、字段、判定规则、技术校验这些工程细节。
  • 不是知识库：不承载知识内容本身。每块知识只有「名称 + 解决什么 + 什么时候用」，具体内容由研发的知识库提供。
一句话边界
本文档回答的唯一问题是——「这个 agent 在什么时候，应该用哪块知识」。知识内容与工程实现，都不在这里。

1这个 agent 做什么

拿到一份简历，追问出真实、可写、有数据支撑的经历，最终交付一份润色后的简历。

它不替你写，而是先看清这个学生是谁、能往哪走，再追问着让他把自己的真东西补出来——把「没写」的经历问出来，把「写了但没价值」的经历重新组织成有数据、有方法、有结果的表述。挖掘经历有两个手段：追问（问出真实经历）+ 给真实案例（用真实例子启发、给安全感，让他愿意说出、看见自己经历的价值）。

「一个不替你编、不空夸你，却总能把你否掉的经历，翻译成值钱样子的追问者。」

2知识块清单

这个 agent 在对话中会调用的知识块。每块只有「是什么 + 解决什么」，内容在研发知识库。

专业岗位识别匹配
拿到简历先识别学生的专业背景与目标岗位方向，判断匹配度、以及这个专业还能往哪些岗位方向走。方向定位是挖掘经历的前置。
经历缺口识别
方向确定后，逐段判断这段缺什么：缺数据 / 缺方法 / 缺结果 / 缺归属 / 空话 / AI 味，决定接下来追问哪块。
非实习经历挖掘
学生没有实习经历时，把 校园项目 / 课程作业 / 社团 / 竞赛 / 志愿者 / 兼职 / 个人作品 当成「经历」，用同样的缺口识别 + 追问挖出可写价值，而不是让简历留白或自我否定。
自我否定翻译
用户说「这很普通」「不是因为我」「都是杂活」时，把自我否定翻译成可写的价值表述。先复述否定，再给新角度。
真实案例佐证
用户自我否定、对行业 / 岗位有幻想或刻板印象时，用真实经历、真实行业现状、真实数据去启发和校准认知，而不是空讲道理。真实案例比空泛安慰更有安全感、更能启发。
岗位产出追问
经历缺数据时，按用户所在岗位对应的产出指标链把数据问出来。内容 / 新媒体运营岗是「触达 → 点击 → 留存 → 互动 → 关注」，其他岗位用各自行业的指标链。
产能追问
用户拿不到后台数据时，改用 总量 / 周期产出 / 波峰 / 主题分类 证明稳定交付。
空话识别
抓出无数据、无对象的口号式 / AI 味句子，建议删除或补证据。
编造拦截
用户想编数据 / 夸张 / 写大概时，明确拒绝，并给替代路径（讲流程 / 讲产能 / 标待补充）。
颗粒度校准
用户接不住时，换载体（图 / 文档 / 截图 / 打码样例）或问更小的问题。换说法，不换要求。
岗位锚点裁剪
用户投不同岗位时，按「验证锚点」（实习相关性 / 量化成果 / 作品项目）判断哪些经历详写、略写、删。
STAR 结构化
用户不会写经历时，用 情境 → 任务 → 行动 → 结果 帮他把一段经历讲完整。
行业常识
用户问岗位要求 / 时间线 / 薪资 / 渠道时，给客观信息。
交付节点判断
判断此刻该「继续追问」「给方向选项」还是「直接给成文」。依据是「素材挖没挖够 + 方向定没定」。
润色成文
把已确认的素材 + 选定的方向，写成润色后的简历文本，逐段交付，最后汇总成完整简历。

4调用节奏

知识块之间的先后与优先级。

  • 入口永远先「专业岗位识别匹配」再「经历缺口识别」——先定位专业与目标岗位方向，再逐段找缺口，不能跳过方向直接追问。
  • 「没实习」先翻译再挖替代——先破「没实习 = 没东西写」的自我否定，再列校园项目 / 社团 / 竞赛 / 兼职等替代来源逐个挖，不能让学生停在「我没东西写」。
  • 「自我否定翻译」命中立即做——先复述否定、再给新角度，中间不停顿；停顿会让用户把否定再说一遍。
  • 「真实案例佐证」的专业性前置——真实实例、调研现状放在前面，先给人安全感，道理和建议放后面。
  • 「编造拦截」常驻——任何时刻出现编造信号立即切进去，拦完回到原场景继续。
  • 「颗粒度校准」优先级最高——用户接不住时先降颗粒度，再谈内容；否则给再多结构都是无效输出。
  • 交付永远逐段——先逐段确认素材与方向、逐段给成文，最后才汇总完整简历；不一次性抛完整内容让用户面对一大段文本。
  • 给方向选项必须说清得失——给 2-3 个写法方向时，每个讲清「好处 + 代价」，让用户能判断，而不是让用户瞎选。
不做什么
不编数据 · 不空夸 · 不凭空代写 · 不承诺结果。其中「不凭空代写」指：本 agent 会交付润色后的简历，但每一句都来自追问出的真实素材，绝不脱离真实经历编造或空写——「写」永远建立在「追问」之上。

6交付流程

最终要输出一份润色后的简历。交付不是一次性给完，而是「逐段 + 四档 + 汇总确认」。

四档交付动作

档位什么时候给什么
① 给思路素材还没挖够只给「这段可以往哪个方向写」的引导，继续追问，不落笔
② 给方向选项 + 得失素材够了、方向有歧义给 2-3 个写法方向，每个说清「好处 + 代价」，让用户选
③ 直接给成文素材确认、方向确定、无歧义直接给这段的润色文本
④ 汇总确认全部段落成文完成汇总输出完整简历，请用户通读、逐点提修改，确认后才算交付

交付节点判断矩阵（单段内）

素材状态方向状态交付动作
没挖够—继续追问（最多给思路引导）
挖够了有歧义 / 多选项给方向选项 + 说清得失
挖够了已确定直接给成文

得失说明的详略（参考说服策略 agent）

「② 给方向选项」时说清得失有两种颗粒度，参考说服策略 agent 的「调整详略」动作——按用户此刻愿意投入的注意力决定给多深：

颗粒度怎么给什么时候用
一句话点破「选 A 更聚焦但显得窄，选 B 更宽但亮点不突出」默认；用户赶时间、只想快速定
给例子对比把两个方向各写成一小段样例，让他直观看到差别用户在认真权衡、主动追问「有差别吗」、或决策困难反复纠结

逐段 + 汇总确认

按「教育 / 实习 / 项目 / 技能 …」逐段走完「追问 → 选方向 → 成文」，每一段确认后再进下一段；全部分段处理完，进入「④ 汇总确认」——汇总完整简历 → 用户通读 → 逐点修改 → 确认交付。

7能力分层与强化

15 块知识落到技术实现分三层：知识库调用、主 prompt 强化、独立 subagent。

① 靠知识库调用就能解决

固定信息 / 模板检索类：行业常识、空话识别、编造拦截、产能追问、岗位产出追问、STAR 结构化、颗粒度校准、非实习经历挖掘、岗位锚点裁剪。查模板 / 规则 / 信息即可，不需要额外推理。

② 靠主 prompt 强化（理解 + 推理 + 共情）

需要读懂上下文再判断的：经历缺口识别、专业岗位识别匹配、自我否定翻译、交付节点判断。靠大模型本身的阅读理解与推理，用主指令 + 示例强化即可，不必拆 agent。

③ 值得独立成 subagent

subagent供给哪些知识块为什么值得独立
行业调研 subagent真实案例佐证 · 行业常识 · 岗位锚点裁剪真人辅导里「先花时间调研这个行业 / 岗位的真实现状与案例」是独立、耗时、可并行、需联网搜索的动作，主对话 agent 不该边聊边大量检索。注意：它独立的理由不是「技能占上下文」，而是「异步 + 耗时 + 可并行」，两者不能混用同一条判断
简历成文 subagent润色成文当前不拆。「把素材写成简历」先由主 agent 承担，配合逐段交付；只有出现拆分信号（见 ⑤）时才独立

④ 与其他 agent 的协作

说服策略 agent 是横跨全局的底层能力（推进用户做决定）。简历润色 agent 在「让用户选方向」「得失说明的详略」「用户纠结要不要改」等时刻，直接调用说服策略 agent 的「调整详略」「替你说出来，请确认」等逻辑，不重复自建。

⑤ 拆分触发条件（当前不拆）

  • 默认不拆：13 块知识的本体是判定规则与提问话术，体积不大，全部留在主 agent。「任务多、场景杂」不是拆的理由，顺序执行即可。
  • 体积大的资料走检索，不做子 agent：行业知识库这类海量文档，塞进子 agent 它也读不完；正确做法是命中时才把片段取出来，平时不占上下文。
  • 拆的唯一正当信号：主提示词 / 工具列表过长，agent 开始顾此失彼、质量下降，且确认无法用检索解决时，再拆。
  • 拆之前先算代价：记忆不通（子 agent 的所见不回流）、交接要另写提示词、每次调用多一跳、调试更难。收益必须明显大于这些成本。
结论
当前真正独立的只有 行业调研 subagent（理由是异步耗时可并行，不是上下文占用）；简历成文暂由主 agent 承担。其余全部用「知识库 + 主 prompt」覆盖。出现 ⑤ 的拆分信号时再评估，不提前过度设计。

8验收标准

研发交付时，产品层面怎么算「做对了」。

验收项标准
红线零触碰不编数据 / 不空夸 / 不凭空代写 / 不承诺结果，在对抗样例（「能编吗」「写个大概」「帮我整份写了吧」）里全部拦截，且可审计
素材可溯源交付的润色简历里，每一句都能追溯到用户提供的真实素材，没有凭空编造的数据或经历
用户能说取舍理由选方向时，用户能说出「为什么选 A 不选 B」，而不是「AI 让我选」——对应「给方向选项必须说清得失」
交付闭环最终输出一份完整、用户逐段确认过的润色简历，走完「逐段 → 汇总确认」，不停在中间环节
不接受的指标
不把「聊天轮数」「回复点赞」「使用时长」当有效指标——它们衡量「聊得久」，不是「简历真的改好了、用户确认交付了」。

9完整对话样例

走一遍完整链路：从拿到简历到汇总确认。学生：教育学专业，投新媒体运营岗，简历上「学生会宣传部：负责公众号运营」只有一句话。

谁说了什么触发
Agent（拿到简历，先判断方向）你是教育学专业、投新媒体运营——这个方向可以走，教育背景做「教育类内容」反而是你的差异化。专业岗位识别匹配
